一套覆盖「采集调度 → 数据加工 → 站点可用性适配」全链路的通用工具集，由若干可独立设计、可独立验证的子系统组成。整体以「契约先行、依赖单向、策略可插拔」为原则，在无第三方运行时依赖的前提下，把大规模采集与加工做成可测试、可恢复、可交接的工程。

核心主张：**在站点准入高度不确定的约束下，用软件可靠性替代对环境的假设**——把不确定性当作一等公民来治理，以调度、兜底与可恢复执行保证长期稳定运行与数据完整性。

## 一、分层架构与依赖方向

- 采集子系统按「客户端层 / 业务编排层 / 并行调度层 / 基础异常层」四层分离，依赖严格单向（调度 → 业务 → 客户端 → 异常）。
- 数据子系统采用「共享核心库 + 薄壳 CLI」两层结构：核心库零副作用、可独立测试，CLI 只负责参数与环境装配。
- 明确各模块边界与装配入口，使子系统可单独运行、单独回归。

## 二、通用采集调度：结果上限的分片策略

- 设计**层级二分拆分算子**作为「单次查询结果数上限」的通用解法：在分类树的多层级上递归二分（高层二分 → 下沉细类 → 按区域再二分），使每个子集可精确计数、可控分页，从而保证全量覆盖。
- 以**覆盖率回验**（接口声明总数 vs 实抓数 + 不符明细）度量数据完整性。
- 控制流由**异常继承体系**承载（过期 / 限流 / 拒绝），驱动「重试 / 刷新 / 重入队 / 退出」策略，与业务逻辑解耦。
- 并发模型为共享任务队列 + 工作窃取式多 worker，避免热点；凭据支持「参数 → 配置文件 → 环境变量」三级回落。

## 三、开闭扩展与数据模型

- 以**注册表 + 策略对象**落地开闭原则，覆盖字段提取、Schema 规则、记录过滤、冲突裁决、口径规则等扩展点，新增能力无需改动既有流程。
- 定义统一的记录去重键优先级与冲突裁决策略（按时间新旧 / 交互确认），使异构数据源的合并口径一致且可插拔。

## 四、高可靠数据管线

- **单写者模型**：所有持久化写入收敛到单一写线程，多 worker 仅入队结果，消除写锁竞争。
- **可恢复执行**：按批推进 checkpoint、仅整批持久化后才推进水位、写锁冲突时保留队首重试、中断时回滚未完成批。
- **大数据量与 I/O**：两段式磁盘搬运（只读源 → 顺序中转 → 目标）避免空间不足并利用顺序读；流式写出避免整文档驻留内存，支撑单库 100GB+ 量级。

## 五、站点可用性适配（可用性工程）

- **采集策略**：以 LLM 语义判定页面类型替代脆弱的正则分类，正则只做优先级排序与无害排除；DFS 优先级队列（最深先出）使在途域名集中、同域限速更有效；对「零命中」页面不再展开，使采集图自然收敛。
- **退避状态机**：统一门禁 + 在途请求隔离（stale）+ 单探针放行 + 冷却梯子，做到 **fail-safe——宁可不采，也不产出无效数据**。
- **对照实验矩阵**：设计「最轻 → 最重」的多路线对照（纯 HTTP → TLS/JA3 指纹模拟 → 真实浏览器 + 兼容性适配），仅改变访问策略单一变量，使结论可横向比较、可量化。
- **多层兼容性适配**：不依赖单一 stealth 方案，而是「库 + 自定义注入脚本 + 兼容性启动参数」多层叠加，保证请求身份一致。
- **并发与礼貌抓取**：浏览器池按「最小在途数」分派 + 全局信号量 + 按域随机延迟；独立线程池承载高并发模型调用。

## 六、可观测性与资源治理

- 失败原因结构化归类（状态码 / 超时 / 异常类型 / 超阈值）并聚合输出。
- 有界队列 + 固定 worker（队满丢最旧）+ 按 tick 起点计时，保证长周期运行内存有界。
- 断点续爬与任务持久化，中断后重跑自动回灌补爬。
